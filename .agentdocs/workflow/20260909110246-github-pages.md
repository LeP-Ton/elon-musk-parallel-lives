# 会话-6：GitHub 源码托管与 Pages 发布适配

## 背景与目标
- 在保留 Sites 的前提下，实现 GitHub 源码托管与 GitHub Pages 发布。
- 不影响现有 Sites 权限与发布流程。

## 约束与边界
- Sites 与 Pages 分离，互不覆盖：Sites 不受 Pages 发布动作影响。
- 不改内容包主路径，仅在构建层处理平台基路径。
- 不新增依赖，不引入新的部署运行时，仅在现有静态链路上交付。
- GitHub 可见性（源码可见/不可见）和 Pages 对外公开是独立决策，需用户最终确认。

## 关键实现
- 资源引用统一改为可带基路径方案，保证 Sites 根路径与 Pages 子路径同时可用。
- 新增 `npm run build:pages`，并加入首页资源前缀校验，避免基础路径漂移。
- 配置 GitHub Actions 发布流，使用 `main` 推送或手动触发执行回归测试、内容校验、双构建再发布。
- 发布链路补齐 `package.json`、`README.md` 与基础文案说明，区分 Sites 与 Pages 行为。
- 保持旧仓库目录结构不变，不将源码目录直接作为网站产物发布。

## 阶段与进展
- 本地环境已完成双端构建与资源校验。
- 当前未执行实际仓库创建/推送上线，远端发布仍等待用户确认代码仓库可见性与创建时间。

## 测试与验收
- `npm test`：通过。
- `npm run validate:content`：通过。
- `npm run build`：通过（Sites 根路径构建）。
- `npm run build:pages`：通过，含首页资源前缀校验。
- 非法 basePath 防线校验（如 `../outside`）触发拒绝，符合预期。
- `TC-606 远端部署验收`：待用户完成仓库发布后再执行。

## 当前风险
- Pages 页面可见性与源码仓库可见性独立，发布时需统一用户配置。
- Sites 与 Pages 的存档不能跨域自动同步，若有迁移需求需导出导入。
