# 会话-9：自动播放需求与实施计划

## 用户新增要求原文

> **新增一个自动播放功能，互动小说的故事能在系统规则内自动动态演化，观众每次看都能有不同结局！**

本文件备份本轮新增需求，不改写 `requirements-original.md` 中的最初需求。

## 实施范围

- [x] 新增独立的自动选择策略，按当前合法选项、人格契合度、压力、精力和自主冲突计算权重，再用独立的种子随机用途抽取选择。
- [x] 复用既有 `choose / advance`、结果概率、条件事件、内容包和结局规则；不硬编码最佳路线或指定结局。
- [x] 新增播放、暂停、1/2/4 倍速、倒计时、选择预告、随机新人生及空格快捷键。
- [x] 选择页与结果页分别停留，按中文阅读量计时；结局停留，不自动覆盖下一轮。
- [x] 手动接管、读档、面板、后台、内容包切换与异常中断；旧计时器失效，返回前台不自行恢复。
- [x] 开新人生前明确提示自动存档会被替换，保留手动槽位；兼容 schemaVersion 1 的旧存档。
- [x] 执行种子路线回归、假时钟测试、内容校验、类型检查和双平台静态构建。
- [x] 更新核心认知、玩法说明、索引与全量 diff 变更文档。

## 验收边界

- 当前内容仍为 15 个核心事件、3 个条件插曲、5 种阶段结局，没有以自动播放冒充扩展剧情。
- 新种子带来路线与结局的多样性，而不是保证相邻两轮结局不同；不为去重而绕过规则。
- 固定 `autoplay-v1`、种子、初始状态、内容及人物版本时可复现；速度与暂停不消耗剧情随机数。
- 当前测试以纯引擎和计时器契约为主；未执行真实浏览器点击、可访问性工具或视觉回归验收。
- GitHub `main` 推送才触发 Pages 自动发布；本地修改、测试或本地提交不会发布，Sites 站点独立管理。
